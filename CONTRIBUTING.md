# Contribution Guide

## Project quality bar
- Keep each project folder self-contained and clearly documented.
- Do not commit API keys, wallet secret keys, private farmer data, or real personal location data.
- Label mocked data and simulated transactions in both the UI and documentation.
- Include screenshots and a short demo script after a working prototype exists.
- Prefer accessible native controls over custom controls where possible.
- Check reduced-motion behavior, keyboard focus, responsive layouts, and error states before calling a screen complete.

## Suggested PR checklist
- [ ] Product behavior is documented.
- [ ] Desktop and mobile states have been reviewed.
- [ ] Data source and units are visible where relevant.
- [ ] Loading, empty, failure, and fallback states work.
- [ ] No sensitive data or secrets are committed.
- [ ] Demo claims match what is actually implemented.
